# Security reporting

<!-- SPDX-License-Identifier: CC-BY-4.0 -->

Report sensitive vulnerabilities using GitHub's
[private vulnerability report](https://github.com/Melihakbulut221/nssoc/security/advisories/new).
Private reporting was enabled and verified for this repository on 21 September
2026. Do not place exploit details, credentials or private data in a public issue.
If the private form is unavailable, open a public issue requesting a private
contact route without including sensitive details.

Include the exact commit and build profile, affected component, expected and
observed behavior, reproduction steps, impact and a minimal sanitized example.
Report vulnerabilities in fetched components to their upstream maintainers as
well, identifying the pinned version and any local adaptation. Do not assume
the upstream and prepared SoC versions behave identically.

This is an experimental hardware/software project with no qualified production
release or guaranteed response/patch schedule. Current development is on
`codex/complete-open-work`; published paper tags are historical snapshots, not
supported product versions. Security properties, fault tolerance, radiation
tolerance and physical qualification are distinct claims; the
[acceptance register](docs/92-product-acceptance.md) records outstanding work.

The maintainer will evaluate a report against a reproducible revision and record
confirmed fixes with tests and limitations. Coordinate public disclosure through
the private report; no fixed disclosure deadline is imposed by this document.
