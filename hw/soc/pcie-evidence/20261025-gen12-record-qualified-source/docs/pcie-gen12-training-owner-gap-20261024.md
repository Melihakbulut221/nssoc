# Gen1/2 training owner: current source gap and next implementation unit

Audit source: `77d16d440b1a489da6041ee7fe4fef6ea0fe80c8`. This is a source audit, not a new native qualification. The companion evidence file records exact SHA256 values for every source below. No RTL or workflow was changed and no job was dispatched.

The codec, raw32 aligner and raw32 transmitter now have independent hosted proofs. The composed raw32 receiver remains pending at run `40108338384`, exact source `493d8ab352330edf5ed01f4340f0cceff6f4ce6f`; its sole job was queued without steps when checked. Its eventual result must be consumed before claiming an accepted receive chain. These blocks provide transport mechanisms; they do not supply the link-training decisions expected by the existing Gen3 hierarchy.

All 138 Verilog/SystemVerilog files under `hw/soc/rtl/pcie/` were searched for TS1, TS2, LTSSM, Polling and Detect at this exact source. Matches describe external scope; no implemented training owner was found in that directory. The concrete missing connections above are based on actual ports and instantiations, not merely this text search.

The next small implementation unit is a per-lane Gen1/2 TS1/TS2 record receiver and transmitter. Proposed files are `soc_pcie_gen12_training_rx.v` and `soc_pcie_gen12_training_tx.v`; these are proposals, not existing modules. The receiver consumes the qualified raw32 RX batch interface (count, data, K, code/disparity errors) and accumulates complete ordered sets across arbitrary one-to-four-symbol batch boundaries. It must preserve link/lane/PAD, N_FTS, advertised rate and training-control fields; separate complete accepted records from malformed/incomplete observations; and discard partial state on flush, disable or a polarity/rate epoch change. It should report normal/inverted training-identifier evidence without declaring link-up or changing polarity itself. Any subsequent CDC transfers complete records with explicit overflow disposition.

The transmitter snapshots one complete training record, emits stable symbol batches until accepted by `soc_pcie_gen12_tx_raw32`, and advances only on acceptance. Reset/flush cancels the partial record. Configuration changes cannot mix fields within an ordered set. The training owner decides when a record is sent or interrupted, when negative RD is requested, and how electrical-idle/rate transitions flush both transports. Independent tests should cover every symbol/batch offset, legal PAD/data fields, both training identifiers and polarity patterns, error insertion at every position, gaps, stalls, incomplete flushes and successive ordered sets. A complete link FSM is not a prerequisite to test this concrete record primitive, and passing it would not qualify a complete link FSM.

Before implementing field interpretation, pin an accessible authoritative Base-specification TS1/TS2 table covering the target Gen3 capability fields. PIPE is useful for the physical-control contract, but it is not that table. [PIPE 7.1 sections 2.4, 8.4.1 and 8.7](https://cdrdv2-public.intel.com/643108/643108_PIPE_Arch_Spec_Rev_7_1.pdf) require support across the advertised rate set and distinguish requested PHY operations from actual completion. Therefore a rate-mode mux cannot simply switch on an LTSSM counter; it must wait for the real PMA completion/clock contract and flush old partial words. [Intel's controller manual section 4.7.2](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/pcie-gbe-controllers-open-source-manual.pdf) documents polarity evidence in training-identifier symbols; COM's complementary code forms alone do not establish polarity. These references do not make NSSOC's custom raw32 seam PIPE compliant.

After this primitive, the remaining central owner must implement actual Detect/Polling/Configuration/Recovery decisions, lane mapping, timers, rate/clock/electrical-idle handshakes and Gen3 equalization/training formatting. It must coordinate the low-rate and Gen3 receive epochs before arming the existing SDS path, and connect the real packet/link engine without discarding accepted events. Low-rate analog operation, full Gen3 serial operation, main-chip integration and timing/layout closure remain separate measured prerequisites.

## Explicit future owner connections

The intended owner is one common-domain link-control state machine with per-physical-lane training observations and acknowledged per-domain commands. Its concrete integration obligations are:

1. In Detect/Polling, consume actual receiver-detect and clock/electrical-idle status, enable the four low-rate receivers, and dispatch complete TS records through four low-rate transmitters. No timer expiry is a substitute for PHY completion. Convert every real discontinuity into an acknowledged flush; `raw_valid_i=0` alone cannot distinguish a harmless word-valid gap from lost stream continuity.
2. During Configuration, validate observed link/lane identities and determine the physical-to-logical lane permutation and negotiated active set. For the current x4 data hierarchy, all four required logical lanes must be present with a consistent negotiated mapping. A narrower partner cannot silently be treated as x4. Either implement its actual narrower data path or retain an explicit unsupported configuration. Preserve each recovered clock with its physical receiver; reorder complete CDC records into logical lanes before the currently fixed `LANE_ID(lane)` descramblers, and apply the inverse permutation to common-clock TX lane data. Do not multiplex unrelated recovered clocks as a shortcut. Commit the mapping only at a flushed epoch boundary.
3. During Recovery/rate change, keep the current normal-data epoch's accepted-event disposition explicit. Request real electrical idle/rate/clock changes, wait for their physical completion, flush both low-rate and Gen3 partial state, and then enter the Gen3 training/equalization sequence with the negotiated mapping. The owner must generate and interpret Gen3 TS fields and command actual analog presets/coefficients; the current normal-data descrambler cannot do this. After the required training transitions, use acknowledged `align_control_i`/`force_realign_i`, wait for `lanes_ready_o`, and issue `arm_i` only in the existing SDS-eligible clean epoch contract.
4. Feed physical link availability and training state into `soc_top` only from these actual owner decisions. Preserve the separate packet-layer initialization result: `soc_pcie_buffered_flow_packets.v:58,79-81` holds FC advertisement/reset behind `link_up_i`, whereas `soc_pcie_flow_packets.v:113-121` produces `initialized_o` from credit exchange. Gating `link_up_i` on `initialized_o` would make initialization circular. Define `retrain_done_i` as the required packet/FC/sequence epoch reset event; it also resets the APB CDC at `soc_top.v:970`. It must not be a copy of COM lock or SDS detection. Ordered event and packet bridges must finish the existing drain/abort contract before exposing a new packet epoch.

These are proposed connections and invariants, not implemented or accepted wiring. The full owner remains open until its actual transitions, timers, per-lane CDC, rate change, x4 mapping, Gen3 training and packet reset behavior are independently tested together.

## Available field evidence and its limits

The [official Teledyne M5x manual, section 4.3.5, printed pages 84-87](https://cdn.teledynelecroy.com/files/manuals/pciesummitm5x_scripting_manual.pdf) explicitly places COM/link/lane/N_FTS at bytes 0/1/2/3. Byte 4 advertises 2.5/5/8 GT/s in bits 1/2/3, autonomous/selectable-de-emphasis in bit 6 and speed change in bit 7. Byte 5 bits 0/1/2 select hot reset/disable/loopback. These are decoded field positions, not permission to copy the analyzer's masks or default values into a compliant receiver. Its API also covers later-generation semantics, so a Gen3 design must not copy later revision fields without checking the target revision.

The [PCI-SIG 3.0 link-number FAQ](https://pcisig.com/section-42644-table-4-5-defines-valid-range-link-number-symbol-1-ts1-ordered-set-0-31-downstream) confirms that field validity depends on port role and state; it discusses the downstream 0-31 link-number range and mismatch handling in Recovery.RcvrCfg. The [PCI-SIG 3.0 FAQ collection](https://pcisig.com/faq?field_category_value%5B%5D=pci_express_3.0) further documents using the most recent low-rate EQ TS2 presets when restarting 8 GT/s equalization, and distinguishes configured-lane TS1 transmission from required SKP/EIEOS insertions. This confirms that the low-rate training stage is an actual prerequisite to the Gen3 path.

The [official Keysight language guide, Gen1/Gen2 TS1/TS2 macros, printed pages 46-47](https://www.keysight.com.cn/cn/zh/assets/9018-70241/programming-guides/9018-70241.pdf) exposes `IsEQ`, receiver-preset-hint and transmitter-preset fields for low-rate training. Thus a receiver that universally requires all identifier positions to equal the standard TS1/TS2 byte would omit EQ variants. The accessible vendor/search evidence identifies this risk; the exact target-revision EQ symbol layout, acceptance rules and consecutive-record criteria still require an authoritative pinned table before implementing them. The guide's convenient macro defaults are not NSSOC configuration defaults.

The current repo's strict-PCS, raw32 boundary and TX transport documents identify training as external; none of those examined documents supplies a pinned full TS1/TS2 field oracle. Intel's indexed Base 2.1 table provides older basic field evidence, but its PDF URL currently redirects to an unavailable page and cannot serve as a complete pinned Gen3 oracle. Remaining source prerequisites include target-revision standard/EQ field rules, reserved-bit handling, transmitter-versus-receiver requirements, state-specific consecutive-sequence conditions, mandatory timer/counter limits, and the physical rate/preset capability contract. Preserve unclassified raw record fields and distinguish unsupported or malformed evidence; never turn missing evidence into a permissive valid/link-up decision.
