# SRAM discrepancies in the first routed soc_top

Inputs are the [first-route GDS and reference](ihp-first-detail-lvs-inputs.md) and the [full database receipt](ihp-sequential-sta-and-first-route-lvs.md). The two macros have different failure signatures.

* Single port, RM_IHPSG13_1P_2048x64_c2_bm_bist. In extended.cir the extracted macro contains 1024 direct instances of RSC_IHPSG13_WLDRVX8. That leaf contains two PMOS (widths 0.9 and 6.48 µm) and no NMOS. The original reference leaf contains those PMOS and two NMOS (1.41 and 1.8 µm). The database flags unmatched extracted nets $3, $4 and $5. The difference is localized to the reported subcircuit boundary. Hierarchy alignment or extraction could redistribute devices across boundaries; these counts do not establish missing silicon.
* Dual port, RM_IHPSG13_2P_256x16_c2_bm_bist. Its database skip lists reference-side child failures. The reference COLCTRL2 subcircuit directly instantiates six RSC_IHPSG13_CINVX2 cells. The original inverter CDL has Z/A as drain/gate and VSS/VDD source and bulk for its 0.705 µm NMOS and 1.62 µm PMOS. The extracted circuit file has no CINVX2 definition and the full database contains an empty layout-side circuit pair for that reference cell. The parent failure cannot establish the location of those devices after flattening.
* Check the leaf records with case-insensitive anchored searches for .SUBCKT in extended.cir and reference.cdl. Inspect their complete records through .ENDS. Inspect the X(RSC_IHPSG13_WLDRVX8 RSC_IHPSG13_WLDRVX8 and X(() RSC_IHPSG13_CINVX2 records in extended.lvsdb.

The native gate was rerun on the pinned unchanged-deck inverter control databases using make check-native-lvs with LVS_TOP=sg13g2_inv_1. The baseline returned 0 with one Match. The faulty reference returned make code 2 with one NoMatch and zero matched top pairs. This establishes the gate's sensitivity on the controls. No SRAM edit or exemption follows from the observed differences. Both product macro comparisons and top-level connectivity remain open.
