# Sparse reconstruction with the original full-column reader

The new cloud experiment uses the preserved actual native5106-column prefix, including its partial final row. It reconstructs every original byte and requires the original reader's16 corruption controls to reproduce exactly. A separate owned46-row fixture contains only complete native rows and a diagnostic point-count header, exactly as the original reader tests do. Its sparse working file must be rejected; complete reconstruction must match every native value and all reader metadata. The original full1us capture gate must reject the short fixture. The original prefix, source contract and reader remain unchanged.

This qualifies the original reader against sparse-prefix reconstruction, not a complete1us waveform or PLL lock/device safety. No native solver or the real892.69ns checkpoint is restored.

A second isolated job measures a possible final static-reader host with only scripts checked out and the already reviewed bounded SDK cleanup. It records exact available bytes and maximum5106-column rows after a4GiB static-reader reserve. It never starts a simulator, does not alter the native12GiB checkpoint/4GiB backing reserves, and does not claim capacity until the actual completed capture size is known. The intended separation is: a sparse working raw for live solver progress; immutable logical archive preservation; a separate static reader consuming the completed whole raw only if exact-size capacity is sufficient. Full logical archive integration still requires implementation and verification.
