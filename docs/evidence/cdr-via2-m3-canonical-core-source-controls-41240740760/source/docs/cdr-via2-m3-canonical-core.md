# Candidate-bound canonical view core

This source-only core uses the actual Via2/M3 candidate physically checked by run 41238994098, source 0b1ec86b35f8cb98928a5687f007a7ccd676f620, release 430168624. Its standalone entry is disabled. The independent adapter must authenticate producer, full same-source controls and an empty result destination before native acquisition or calling these APIs.

The qualified 6f0dd8 projection primitive is unchanged. It retains every original reference child and both original layout metadata records, copies the new flat LVS and candidate geometry, and labels the new metadata as derived. It never imports an old graph or RC result as a new observation.

The core extracts only exact named frozen function definitions. Historical module imports, main functions and admission code are not executed or replaced. Parent geometry, source-pin recovery and native planes use the same function bodies with the existing explicit top-name derivation. Seven identity functions and four normalization functions remain exact. The identity comparator's checks remain exact; its return metadata records observed native-net counts. The graph index retains full terminal/port ownership, empty-partition and unsplit-conductor checks while deriving topology-dependent counts from the complete observation instead of historical 113/238/114 constants.

The native path must independently reproduce all 500 device identities, 1446 terminals, 25 ports, original primitive transforms/parameters/locations and 978 logical anchor identities, including 953 metal and 493 intrinsic-body references. Every observed conductor partition is checked across all seven metal and six via layers against the actual sixteen declared Via2/M3 additions. Empty-to-present layers are handled explicitly. The original serialized generation JSON is hash-bound; its proposal is never promoted to a measured guard result.

APIs:
- prepare(reference, physical, out, source_root, config, reference_members, physical_members) creates out/candidate and derivation records.
- derived(mode, view, source_root, config), with mode planes or recover, executes the selected exact frozen function after the separate hosted entry's authorization.
- Four unchanged worker files are executed in separate pinned runtime processes, in order probe01.py, locate01.py, anchors01.py, dedup01.py.
- verify(reference, physical, view, out, source_root, config) writes canonical-view-qualification.json and full original/current identity, twelve acquired-witness fault controls, all-layer material and complete report-input bindings.

Hosted controls use synthetic full-sized JSON graphs, actual declaration metadata and synthetic Pya Region algebra. They are not new candidate CAD observations. Native archives remain cloud-only. This stage does not extract RC, simulate waveforms, claim electrical recovery or accept a complete PHY. Subsequent fresh extraction must retain every actual new R/C branch, coupling and boundary capacitor, all seven intrinsic MIM devices, and observable ownership. Historical R/C/vector counts are not new-candidate results.
