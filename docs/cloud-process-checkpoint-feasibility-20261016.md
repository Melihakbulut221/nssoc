# Cloud process checkpoint feasibility

The full PLL transient currently exceeds a single hosted job budget. A waveform prefix cannot restore simulator state. This isolated experiment checks a possible process-state continuation route without changing the active physical PLL run or its acceptance criteria.

Docker/CRIU is experimental and primarily targets same-host restore ([Docker reference](https://docs.docker.com/reference/cli/docker/checkpoint/), [CRIU integration](https://criu.org/Docker)). The test records the actual kernel, CRIU/Docker versions and immutable image ID/digest, then checkpoints a process with64MiB of mutable heap, RNG and floating-point state and an open binary output file. It restores into a separate container and requires byte-exact output and heap checksum against the uninterrupted deterministic sequence, an unchanged file prefix and exactly one entrypoint invocation. Truncation, state corruption and cold restart must be rejected.

A pass does not prove native ngspice/VBIC/OSDI continuation or cross-host migration. Those require additional exact-runtime, file-tree and continuous-versus-restored native capture comparisons. Full1us acquisition and all original acceptance limits remain mandatory. The ephemeral fixture does not have repository tokens, opens no network sockets and never touches other running jobs.

The source-pinned CRIU build successfully created a checkpoint, but Docker28.0.4 rejected custom restore directories. Hash-exact transfer to the clone standard directory passed; Docker then failed before calling CRIU with `/proc/0/ns/net` missing. Cloud diagnosis38888552215 preserved the actual logs. The next attempt uses host network only on the disposable fixture runner, matching the reported Docker28 workaround ([upstream issue50750](https://github.com/moby/moby/issues/50750)). No real simulation or process-state acceptance has been established.

Same-host separate-container probe38888817734 passed all3000binary records, the64MiBheap digest, one-entrypoint and corruption controls. Cross-job attempt38889553961 stopped before native restore because it incorrectly assumed runner hostnames are unique. Its source and target jobs reported the same hostname. The corrected test explicitly requires different GitHub run IDs and an initially empty Docker store, preserves host/kernel/boot observations and leaves distinct-physical-host proof false. This is not a relaxation of numerical/state checks, and it cannot establish native simulator continuation by itself.
