# Native physical845 checkpoint with portable libc dispatch

This experiment addresses a measured CPU-dependent portability failure: the immutable source4ns native process restores bit-exact on a separate Intel Xeon8370C job38903625322 but fails SIGILL on AMD EPYC7763 in38901137382. It does not assume that the cause is already identified; the original source checkpoint remains preserved and its AMD trap diagnosis runs separately.

The new source controller disables glibc AVX512F/CD/BW/DQ/ER/PF/VL and RTM IFUNC choices at every fresh native process start via GLIBC_TUNABLES. These names and the relevant memset/memmove dispatch branches are present in glibc2.39 source: https://github.com/bminor/glibc/blob/glibc-2.39/sysdeps/x86/cpu-tunables.c ; https://github.com/bminor/glibc/blob/glibc-2.39/sysdeps/x86_64/multiarch/ifunc-memset.h ; https://github.com/bminor/glibc/blob/glibc-2.39/sysdeps/x86_64/multiarch/ifunc-memmove.h . This changes libc implementation selection, never tolerances, solver, circuit, device parameters, sources or probes.

The host reference must exactly reproduce original4ns payloadSHA633f0aaa88c7c08655e6d1b7f99d08284916746331f7c50c03091161ca2bbd1e. Host/container and native checkpoint/restore then compare every12818row and34voltage probe with single-entrypoint and all3corruption controls. Actual source CPU/kernel/capability images and Docker native environment are recorded. Failed or changed trajectories remain failures. Cross-job transfer, original1us acquisition and fullPHY are not accepted by this bounded source test; separate destination verification is required after a successful immutable source capsule exists.
