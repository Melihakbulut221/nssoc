# Source-bound onehot critical branch repair trial

Run 39080271087 parsed the full native post-CTS paths from run 39061293959. Slow setup remains -6.199764 ns; fast hold remains -0.391465 ns. The previous setup repair resized only 64 cells and stopped without closing all endpoints. The worst setup paths include the Ibex register-file cone, PCIe internal control paths and PCIe TX outputs. The worst hold path starts at pcie_rx_valid_i.

Nine internal positive buffers on the reported worst setup paths have >=0.35 ns slew and >=0.25 ns cell delay; several exceed 1 ns. This trial removes only those exact buffers before native electrical/setup/hold repair, allowing the native tool to rebuild those branches. Native preflight verifies every name, master and signal connection, rejects IO/clock/fixed targets, and proves all retained instance attributes and clock connections unchanged during contraction. Original periods 20/4/8/8 ns, 5% derate and setup/hold margins are preserved.

The approach follows the OpenROAD [specific-instance remove_buffers guidance](https://openroad.readthedocs.io/en/latest/main/src/rsz/README.html). It is a separate measured candidate, not an accepted optimization. It revalidates nine source proofs, native boot and protocol source hashes, reproduces the exact original three-corner timing before mutation, then checks new timing and full retained equations using native negative controls. All reports and failures are published. No path is waived, the original repaired database is immutable, and final routed/extracted timing remains open.
