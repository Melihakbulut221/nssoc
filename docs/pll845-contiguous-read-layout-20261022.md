# Full PLL capture reader storage adaptation

The complete native1us source39750949326 is preserved. Reader39798792510 reached its350-minute limit; its published RUNNING snapshot is not a completed waveform or acquisition verdict. The previous wrapper only copied the original reader report in Python finally; abrupt termination could lose that diagnostic copy. The new workflow copies it again in its always-publication step.

The former reader presents strided views of a130,771,392,219-byte file to repeated edge, window and cycle operations. This is a plausible I/O bottleneck, not a proven diagnosis of the uninstrumented timeout. The new adapter declares exact source edits and adds phase/RSS/I/O heartbeat and stack diagnostics.

After the unchanged full5106-column finite/time/header/hash gates, eight analyzer inputs are copied in4096-row chunks into contiguous binary64 arrays (204,890,240 bytes for the actual capture). Every copied chunk is bit-compared. Every other original column remains available and the complete ordinary raw file and public capture remain intact. No sample, current column, time window, load, frequency, gate or circuit is removed or changed. The original acquisition functions and all6167 terminal envelopes execute unchanged.

Cloud controls compare every acquisition and cycle output exactly on passing and two rejecting fixtures, test malformed inputs, verify all source hashes and execute the existing original import/contract/envelope controls. Fixture success is not physical acceptance. The full reader runs only by explicit dispatch after controls. A completed native acquisition rejection remains a failure even when full terminal diagnostics can be computed. Terminal voltage envelopes do not establish all device currents, PVT reliability, CDR closure, PCIe compliance or chip timing.

All work and resulting artifacts stay on GitHub-hosted runners/releases. No local checkout or simulation is used.
