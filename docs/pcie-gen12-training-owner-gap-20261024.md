# Gen1/2 training owner: current source gap and next implementation unit

Audit source: `77d16d440b1a489da6041ee7fe4fef6ea0fe80c8`. This is a source audit, not a new native qualification. The companion evidence file records exact SHA256 values for every source below. No RTL or workflow was changed and no job was dispatched.

The codec, raw32 aligner and raw32 transmitter now have independent hosted proofs. The composed raw32 receiver remains pending at run `40108338384`, exact source `493d8ab352330edf5ed01f4340f0cceff6f4ce6f`; its sole job was queued without steps when checked. Its eventual result must be consumed before claiming an accepted receive chain. These blocks provide transport mechanisms; they do not supply the link-training decisions expected by the existing Gen3 hierarchy.

All 138 Verilog/SystemVerilog files under `hw/soc/rtl/pcie/` were searched for TS1, TS2, LTSSM, Polling and Detect at this exact source. Matches describe external scope; no implemented training owner was found in that directory. The concrete missing connections above are based on actual ports and instantiations, not merely this text search.

The next small implementation unit is a per-lane Gen1/2 TS1/TS2 record receiver and transmitter. Proposed files are `soc_pcie_gen12_training_rx.v` and `soc_pcie_gen12_training_tx.v`; these are proposals, not existing modules. The receiver consumes the qualified raw32 RX batch interface (count, data, K, code/disparity errors) and accumulates complete ordered sets across arbitrary one-to-four-symbol batch boundaries. It must preserve link/lane/PAD, N_FTS, advertised rate and training-control fields; separate complete accepted records from malformed/incomplete observations; and discard partial state on flush, disable or a polarity/rate epoch change. It should report normal/inverted training-identifier evidence without declaring link-up or changing polarity itself. Any subsequent CDC transfers complete records with explicit overflow disposition.

The transmitter snapshots one complete training record, emits stable symbol batches until accepted by `soc_pcie_gen12_tx_raw32`, and advances only on acceptance. Reset/flush cancels the partial record. Configuration changes cannot mix fields within an ordered set. The training owner decides when a record is sent or interrupted, when negative RD is requested, and how electrical-idle/rate transitions flush both transports. Independent tests should cover every symbol/batch offset, legal PAD/data fields, both training identifiers and polarity patterns, error insertion at every position, gaps, stalls, incomplete flushes and successive ordered sets. A complete link FSM is not a prerequisite to test this concrete record primitive, and passing it would not qualify a complete link FSM.

Before implementing field interpretation, pin an accessible authoritative Base-specification TS1/TS2 table covering the target Gen3 capability fields. PIPE is useful for the physical-control contract, but it is not that table. [PIPE 7.1 sections 2.4, 8.4.1 and 8.7](https://cdrdv2-public.intel.com/643108/643108_PIPE_Arch_Spec_Rev_7_1.pdf) require support across the advertised rate set and distinguish requested PHY operations from actual completion. Therefore a rate-mode mux cannot simply switch on an LTSSM counter; it must wait for the real PMA completion/clock contract and flush old partial words. [Intel's controller manual section 4.7.2](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/pcie-gbe-controllers-open-source-manual.pdf) documents polarity evidence in training-identifier symbols; COM's complementary code forms alone do not establish polarity. These references do not make NSSOC's custom raw32 seam PIPE compliant.

After this primitive, the remaining central owner must implement actual Detect/Polling/Configuration/Recovery decisions, lane mapping, timers, rate/clock/electrical-idle handshakes and Gen3 equalization/training formatting. It must coordinate the low-rate and Gen3 receive epochs before arming the existing SDS path, and connect the real packet/link engine without discarding accepted events. Low-rate analog operation, full Gen3 serial operation, main-chip integration and timing/layout closure remain separate measured prerequisites.
