## Receive contract

The actual soc_pcie_gen12_raw32_rx instance owns bit alignment, explicit polarity, decoding and received running disparity. Its previous registered one-to-four-symbol batch is consumed on each RX edge. A candidate starts at decoded K28.5 with its actual COM flag and no code error. A disparity error on that COM is retained, not silently corrected. Bytes before a candidate are outside records. Once collection starts, exactly sixteen symbols are retained, including every byte, K flag, code error, disparity error and COM flag. An internal COM does not restart or truncate the record. Completion can occur at any batch slot; remaining slots can begin the next candidate. No repeated 4A/45 pattern or EQ field value is assumed.

Two complete-record FIFO slots provide explicit bounded storage. Ready consumes the oldest record; a simultaneous pop frees space for a newly completed record. When a third complete record has no room, overflow becomes sticky and new collection halts until flush/reset. Already queued complete records remain drainable. This exposes a real discontinuity to the future owner; it is not permission to continue an apparently complete training history. Output data is zero when record-valid is false. A queued record remains unchanged during backpressure.

Reset, disable, explicit realignment or polarity change flushes the partial record, both queued records and the underlying receiver's pending batches together. The current raw word is also discarded by that existing receiver contract. Valid gaps alone preserve partial records and allow already registered batches to retire. RX candidate processing adds one clock after the existing registered decoded batch. Each direction has its own clock/reset; no control or payload CDC is invented.

## Transmit contract

One accepted request contains all sixteen bytes/K flags and an explicit caller-owned force-negative-RD flag. All sixteen K requests are checked before any prefix can enter the qualified raw32 TX FIFO. Illegal K anywhere consumes and reports the record without appending any symbol or changing RD; previously queued raw words can still drain independently.

A legal record is captured atomically. Four successive four-symbol batches traverse the actual soc_pcie_gen12_tx_raw32 instance; each chunk advances only when that instance accepts it. Input fields may change after record acceptance without changing the buffered record. The explicit RD force applies only to the first accepted batch and is held through backpressure. It is not asserted automatically for every record. The underlying transmitter maintains ordinary continuous RD across all other chunks and records.

tx_record_queued_o pulses when the last chunk enters the raw32 FIFO. It is not serial-wire completion. A request accepted at edge N first becomes eligible to enter the raw32 FIFO at a later edge. The record stage permits the next record only after the previous last chunk is accepted; the existing FIFO can cover that one-edge staging interval. raw-ready and stream-active retain their existing demand/underflow meaning. Flush/reset/disable clears both the record stage and raw32 FIFO. The record layer does not require COM or enforce TS field semantics on transmit; the future actual owner must construct and schedule valid training sequences.
