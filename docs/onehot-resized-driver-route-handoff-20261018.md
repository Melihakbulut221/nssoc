# Resized data-driver routing handoff

The `onehot-resize-route-cloud.yml` accepts an exact successful preparation run, head, summary SHA256 and manifest SHA256. The controller retains the complete prior boot/RTL/CTS/equation-proof/route ancestry checks and then additionally verifies the actual 39149110568 routed baseline and its resizing proof. A failed preparation cannot launch routing.

The sized candidate must preserve all 146728 instances and nets except the explicitly recorded positive buffer masters and legal target placement. Original other-cell geometry, PG, ports and NDRs must remain unchanged. Post-route comparison checks the sized geometry itself and accepts only added antenna diodes, with the original four fault controls retained.

The established native global/detail router is reused. Inherited signal routing, parasitics and timing metrics are discarded. Original 20/4/8/8 ns clocks, 5 percent derating, load/input constraints and all three cell corners stay unchanged. There is one antenna repair round per saved cloud run, and any remaining antenna violation remains an unmet gate. Native extraction and all-corner setup/hold/slew/cap/fanout reports follow routing. No pass is inferred from job success; complete zero-violation gates and additional signoff are still required.

The workflow is now registered by a workflow-path-only push with defaults bound to inspected successful preparation 39160200022. Manual dispatch can override these pins, but it must still pass all source and success checks. A first dispatch attempt before registration returned HTTP404 and launched no job. Ordinary code or documentation commits do not trigger another route. All native work and retained archives remain on GitHub.
